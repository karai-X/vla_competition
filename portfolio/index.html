OVERVIEW

摂動が加わっても、ぶつけずに解く

LIBERO のロボット操作タスクを、背景・照明・カメラ視点・物体配置・ロボット初期姿勢・センサノイズといった摂動が加わった状態でも、 周りの物体に衝突せずに解けるようにすることを目標に、LIBERO-Plus で学習済みの VLA OpenVLA-OFT（7B）を、自前で生成したデータでファインチューニングしました。 ここでは、その実装の抜粋と、試行錯誤から得た知見をまとめています。

背景・照明の摂動 90% → 99% タスク成功率。ファインチューニングなし → あり（100件）
視点・配置・初期姿勢・ノイズの摂動 80% → 84% タスク成功率。ファインチューニングなし → あり（100件）
学習データ 5,830 エピソード。公開データ＋独自生成・品質改善

ファインチューニングなしとの比較

ベースにした学習済みモデル Sylvest/openvla-7b-oft-finetuned-libero-plus-mixdata をそのまま動かした場合と、 ファインチューニング後のモデル（追加学習 計25,000更新）を、LIBERO シミュレータの同じシナリオ・同じ評価手順で比べました。 衝突は「操作対象以外の物体を1mm超動かしたら衝突」と定義しています。

やったこと

モデル

  • LIBERO-Plus で学習済みの OpenVLA-OFT に LoRA rank 32 を追加し、Action head と proprio projector を学習（ベースモデル）
  • 直前3 Actionの履歴入力を、ゼロ初期化した分岐で既存のproprioトークンへ加算（元の出力を壊さずに拡張）
  • 8-step × 7次元のAction chunkを予測し、実行長は1/4/8を比較して決定

データ

  • LIBERO シミュレータで、物体配置・初期姿勢・カメラ・照明・センサノイズを摂動した成功かつ衝突なしの軌道を生成
  • 同じ初期状態のまま軌道を短縮・平滑化し、指標の重みをどう置いても悪化しない改変だけ採用する品質ゲートを設計

MODEL

摂動に強いモデルを、さらに衝突しない方向へ

ベースには、Hugging Face で公開されている Sylvest/openvla-7b-oft-finetuned-libero-plus-mixdata（revision a85655eに固定）を使いました。 OpenVLA を LIBERO 向けに改良した OpenVLA-OFT を、さらに摂動つきのデモで追加学習したモデルです。

1. OpenVLA：画像と言語を読む7Bのモデルに、Actionを「単語」として出させる

OpenVLA は、画像と言語を理解する視覚言語モデル（VLM）を、ロボットの操作データでさらに学習させた 7B パラメータのモデルです。 土台にしている VLM は Prismatic-7B で、次の3つの部品からできています。

画像エンコーダ

DINOv2（自己教師あり学習。物体の形や空間的な位置関係をよく捉える）と SigLIP（画像と言語の対応で学習。物体の意味を捉える）の2つを並列に使い、パッチごとの特徴を連結します。ロボット操作では「何があるか」と「どこにあるか」の両方が要るためです。

言語モデル

Llama 2 7B。画像の特徴は MLP プロジェクタで Llama 2 の単語埋め込みと同じ空間へ変換され、言語指示のトークンと一緒に並べて入力されます。 Prismatic の段階で、画像とテキストの対話データで学習済みです。

Actionの出し方

手先の移動量・回転量・グリッパの7次元を、それぞれ256段階に区切って離散トークンにします（Llama の語彙のうち使われにくい256個を流用）。 モデルは文章を書くのと同じように、7個のトークンを1つずつ生成し、それを連続値に戻してロボットへ送ります。

この VLM を、さまざまなロボット・タスクを集めた Open X-Embodiment の約97万軌道で学習したのが OpenVLA です。 画像エンコーダも含めてモデル全体を更新しています。

2. OpenVLA-OFT：Actionの出し方を、ロボット向けに作り直す

OpenVLA の「1トークンずつ生成する」出し方は、1ステップ分のActionを出すのにLLMを7回動かす必要があり、遅く、細かい連続値も表しにくい。 OpenVLA-OFT（Optimized Fine-Tuning）は、モデル本体はそのままに、入出力と学習の仕方を次のように変えます。

OpenVLAOpenVLA-OFT
入力カメラ画像1枚 ＋ 言語指示正面＋手首の画像2枚 ＋ 言語指示 ＋ proprio（ロボットの関節・手先の状態）
出力1ステップ分（7個の離散トークン）8ステップ分 × 7次元の連続値（Action chunk）
生成の仕方自己回帰で1トークンずつ（7回）空の入力を並べ、1回の推論で全部を並列に出力
出力層LLMの語彙（言語モデルのヘッド）LLMの隠れ状態から連続値を出す MLPのAction head
損失トークンの交差エントロピー連続値の L1 誤差
学習方法全パラメータLoRA（rank 32）＋ Action head ＋ proprio projector

今回使ったモデルは、この方法で LIBERO の Spatial / Object / Goal / Long の4タスク群を1つのモデルとして学習したものが元になっています。

3. LIBERO-Plus で追加学習

LIBERO-Plus は、元の LIBERO のデモを背景・照明・カメラ視点・言語の言い換え・センサノイズ・妨害物などを変えた環境で再生し、成功したものを集めたデータです。 2 の OFT モデルを、このデータで追加学習したのが今回のベースです。配布物に含まれる統計では 14,347 軌道・約224万ステップ・40タスク。

ベースに足りなかったもの

ベースは既に摂動に強く、背景・照明の摂動を加えた100件のうち90件を成功させます。それでも、次の点は学習の対象になっていませんでした。

  • ロボットの初期姿勢の変化：LIBERO-Plus は評価には初期姿勢の摂動を含みますが、学習データには入っていません
  • 周りの物体との接触：元のデモは「タスクを達成したか」で集められており、非対象物体を動かしたり擦ったりした軌道も含みます
  • 新しい物体の追加や、無関係な物体の大きな移動：対象の周りが混み合った配置

そこで、これらの摂動を加えた状態で成功し、かつ非対象物体を動かさない軌道を生成し、それを教師にしてファインチューニングしました（データ）。

モデル名の「OFT+」は LIBERO-Plus で追加学習したことを指します。 出典：OpenVLA、OpenVLA-OFT、LIBERO-Plus、モデルカード。

構成

青枠が今回の学習対象。ベースの重みは凍結し、LoRA・Action head・proprio projectorを学習。出力は [dx, dy, dz, droll, dpitch, dyaw, gripper] の7次元×8ステップ。

推論経路で決めたこと

前処理は1つの関数だけ

LIBEROのカメラ画像は上下左右が反転しているため、front / wrist の両方を180°回転してからモデルへ渡します。 回転・リサイズ・補間を学習ローダと推論サーバで別々に実装すると必ずずれるので、 prepare_libero_camera() を共有し、角に目印を置いた非対称画像をゴールデンテストにしました。

gripperの符号規約を境界で変換

LIBERO生データは -1=開 / +1=閉、OFTの教師は 0=閉 / 1=開。 ローダの境界で g_oft = (1 - g_libero) / 2 と変換し、出力時に逆変換します。データ版ごとに規約を宣言させ、宣言のないデータは読み込みません。

8本予測して、何本実行するか

モデルは常に8ステップ分を予測し、実行長だけを1 / 4 / 8で比較しました。背景・照明の摂動100件でのタスク成功は、実行長1で74件、4で87件、8で96件。 再観測を増やせば修正が効くとは限らず、8ステップをまとめて実行するほうが安定していました。

正規化統計を確実にモデルへ渡す

Action の正規化統計は全タスク共通の1つに固定し、指示文やタスク名で切り替えません。 LoRA で包んだモデルでは外側に設定した統計が内側の推論関数から見えないことがあり、内側のモデルへ直接渡して一致を検査するようにしました。

指標の重みをどう置いても悪化しない軌道改善

成功して衝突しないことに加えて、短く・滑らかに動く軌道を教えたい。ただ、ステップ数・jerk・SPARC（滑らかさ）・手先の経路長・回転量のどれをどれだけ重視すべきかは一意に決まりません。 そこで、同じ初期状態・同じシーンのまま、待機区間の削除・リタイミング・平滑化などの候補を物理実行し、次をすべて満たす改変だけを採用しました。

  1. 成功し、全20Hzステップで非対象物体の変位が1mm以下
  2. 280物理ステップ以内（評価上限300に余裕を持たせる）
  3. 5指標それぞれを ref / (ref + cost) で正規化し、各重みを10〜30%（総和1）で動かした最悪ケースでも改善量が 1e-4 を超える
  4. 保存したActionを別プロセスで再生しても同じ結果になる

最悪ケースの重みは線形計画の端点なので、指標の改善量を並べ替えて貪欲に割り当てるだけで求まります（weight_extreme()）。

LESSONS

失敗から得た知見

うまくいったことより、うまくいかなかった理由のほうが再利用できます。 観測した事実と、そこから下した判断を分けて書いています。

01 · 推論経路

まずファインチューニングなしのモデルで、成功率が出ることを確かめる

観測
自作の推論サーバに画像の180°回転が入っておらず、それまでの評価値が無効になった。正しい前処理で測り直すと、validation lossが下がり続けていたrunは元のモデルより悪かった（成功33/130、元は49/130）。
判断
新しい推論経路を使う前に、公開重みをそのまま通して非ゼロの成功率を確認するゲートを必須にした。前処理のバージョンが記録されていない評価値はモデル比較に使わない。
02 · データ規約

gripperの符号とloss maskは、ファイルにあるだけでは効いていない

観測
生成データのgripperがLIBERO規約（−1=開）のまま、OFT規約（0=閉）のデータと混ざっていた。さらに失敗区間のmaskがlossまで伝播しておらず、故意の失敗Actionまで教師にしていた。
判断
その学習runは棄却。データ設定にgripper規約を必須項目として宣言させ、値域とmask付きlossを単体テストと実batchのshapeで確認するようにした。
03 · 学習率

強いモデルへの追加学習は、学習率が既存能力の保持を決める

観測
標準デモだけで追加学習しても、LR 5e-5では500〜1,000更新で元より悪化（130タスクで成功49→42）。LR 1e-5にすると2 seed合算で成功95→94・衝突なし成功74→75・衝突126→116と、ほぼ保持できた。
判断
新しいデータを混ぜる前に「標準データだけで元の性能を保持できるか」を先に確かめる。ここが通らない状態でデータを足しても、効果と忘却を切り分けられない。
04 · 損失関数

平均L1が良くなっても、動きは「縮んで」いる

観測
validationの非正規化MAEは4.97%改善したのに、次元別の符号付き誤差はx方向 −0.014→−0.056、z方向 −0.029→−0.070と悪化。全suiteで移動量が系統的に小さくなっていた。
判断
L1の集計値だけでなく、次元別の符号付きバイアスを必ず記録する。補助損失として次元ごとの符号付き平均誤差を罰する項（masked_action_signed_bias_loss）を実装して比較した。
05 · 多峰性

ほぼ同じ入力に異なる教師があると、L1 headは中間を出す

観測
75.7万の学習入力のうち、指示が同じで画像・proprioがほぼ同一なのに教師Actionが0.05以上異なる別エピソードのペアが12,737組あった。その32組だけを200更新繰り返し学習しても、2つの教師を出し分けられたのは0組。予測は2つの教師の間に留まった。
判断
L1 headは条件付き中央値しか表現できない。分岐点の教師を揃えるか、diffusion headを独立に比較するべき問題で、「L1で多峰性に対応できている」とは言えない。
06 · 評価の解釈

衝突フラグの原因は、受動的な再生で確かめる

観測
4タスクで衝突が多発し、モデルが物にぶつかっていると考えた。同じ初期状態でロボットを動かさない対照と比べると、衝突フラグ27件はすべて、開始0.05〜0.10秒にドレッシングの瓶が約1.03mm沈み込む物理の初期化によるものだった。ロボットからの接触は0件。
判断
評価開始前にゼロActionで10ステップ待機してから判定する手順に切り替えた。衝突を減らす学習を始める前に原因を確認していなければ、存在しない問題を学習で解こうとしていた。
07 · 指標の選び方

validation lossの上昇は、成功率の低下を意味しない（逆も）

観測
ある追加SFTでは固定validationのlossが32%上昇した。一方、validation lossが下がり続けていたのに、シミュレータでの成功率は元のモデルを下回るrunもあった（知見01）。
判断
lossはモデル選定の最後の指標にする。優先順位は 衝突なし成功 → 成功 → 衝突 → validation loss → ステップ数・滑らかさ。途中のcheckpointは削除せず残す。
08 · 実験管理

主要な変更は1回に1つ。悪化した実験も消さない

観測
データ源の除外・比率の半減・更新数100/200/500・学習率の比較を1つずつ行った結果、どれも元のモデルを再現性高く上回れないことが分かり、問題が「データの量」ではなく「推論時のAction縮小」にあると絞り込めた。
判断
実験ごとに仮説・起点のcheckpoint・データ版・seed・結果・採否と理由を残す。棄却した実験も残すことで、同じ失敗を条件不明のまま繰り返さずに済んだ。
